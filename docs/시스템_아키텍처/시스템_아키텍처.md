## 시스템 아키텍처
GGogit 프로젝트 시스템 아키텍처입니다. 아래의 다이어그램은 시스템의 전체적인 구조를 보여줍니다.

```plantuml
@startuml
title GGogit 시스템 아키텍처

frame "MINI PC taecobug001 Ubuntu 24.04.1" {
    frame "Docker" {
    
        frame "Docker Compose db" {
            database "Main 운영 데이터베이스\n DB: mariadb" as mainDb
            database "Test 데이터베이스\n DB: mariadb" as testDb
        }
        
        frame "Docker Compose main\nbranch 'main'" {
            [Spring Boot App] as mainApp
            [Nuxt Build App] as mainNuxt
            [Nginx\nwww.ggogit.io] as mainNginx
            
            mainDb --> mainApp
            mainApp --> mainNginx
            mainNuxt --> mainNginx 
        }
        
        frame "Docker Compose test\nbranch 'alpha'" {
            [Spring Boot App] as testApp
            [Nuxt Build App] as testNuxt
            [Nginx\nalpha.ggogit.io] as testNginx
            
            testDb --> testApp
            testApp --> testNginx
            testNuxt --> testNginx
        }
    }
    
    frame "Jenkins" {
    
        [Jenkins\nBuild] as jenkinsBuild
        note right of jenkinsBuild: Jenkins Pipeline "alpha", "main" 브랜치 빌드
        [Jenkins\nTest] as jenkinsTest    
        [Jenkins\nDeploy] as jenkinsDeploy
        
        jenkinsBuild --> jenkinsTest
        jenkinsTest --> jenkinsDeploy
    }
}
@enduml
```

## `Docker Compose db` 구성
2개의 데이터 베이스 존재 (운영 데이터베이스, 테스트 데이터베이스)
- 운영 데이터베이스: `mariadb`
운영에 사용되는 데이터베이스
  
- 테스트 데이터베이스: `mariadb`
테스트에 사용되는 데이터베이스

## `Docker Compose test` 구성
`alpha` 브랜치에 배포되는 컨테이너 구성 `alpha` 브랜치에 코드를 `PR` 하면 `jekins`를 통해 `alpha` 브랜치에 배포

- Spring Boot App: `testApp`
- Nuxt Build App: `testNuxt`
- Nginx: `testNginx`

빌드 순서
1. 코드 작성 후 `aplha` 브랜치에 `PR`
2. `github`에서 `Jenkins`로 `PR` 전달
3. `Jenkins`에서 `PR`을 받아 `test` 빌드
4. `Jenkins`에서 `test` 빌드 후 `test` 테스트
5. `Jenkins`에서 `test` 테스트 후 `test` 배포

## `Docker Compose main` 구성
`main` 브랜치에 배포되는 컨테이너 구성 `main` 브랜치에 코드를 `PR` 하면 `jekins`를 통해 `main` 브랜치에 배포

- Spring Boot App: `mainApp`
- Nuxt Build App: `mainNuxt`
- Nginx: `mainNginx`
